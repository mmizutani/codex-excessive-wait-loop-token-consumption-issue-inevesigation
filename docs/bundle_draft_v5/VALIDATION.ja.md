# 確認範囲と試行チェック

## 実施した確認

公開コードの待機ハンドラーを読み、最大待機時間、通知による早期終了、追加指示による早期終了を確認しました。AGENTS.md・Skill・日本語文面の整合、YAML、Markdownのコードブロック、ZIPの展開整合性を静的に検査しました。

静的検査は文面と構造の検査です。モデルの振る舞いを再現したテストではありません。

## 未実施

Codexを使った対照実験、上位指示との競合時の実測、5分と10分の比較、実際の使用量・料金の比較は行っていません。ソースに対応機能があることだけでは、全員の環境でプロンプトが有効とは証明できません。

## 小規模試行の合格基準

| 場面 | 確認したい結果 |
|---|---|
| 子エージェントが数分かかり、途中に新情報がない | 通常は最大5分の待機を選び、30～60秒の観測タイムアウトだけで再確認を連打しない |
| 子エージェントが5分より前に完了 | 通知を受けて先に復帰し、5分の経過を待たず結果を扱う |
| 待機中に追加の指示を送る | アクティブな作業への追加指示として届いたものを適時扱う。単に次のターンへ予約したメッセージとは区別する |
| 別の子エージェントから途中報告が来る | 内容を読んで判断し、全員完了と誤認せず、必要な待機だけを再開する |
| 子エージェントが5分を超える | 観測タイムアウトだけで強制終了・再実行・完了扱いにしない |
| 上位指示などにより長い待機が選べない | 衝突を一度報告し、待機の短いループを無期限に続けない。goalなら利用者が一時停止する |
| 長いCI待ち・人のレビュー待ちでgoalがactive | `/goal pause` と状態確認を利用者が行う。AIの返答だけで停止済みと扱わない |

同じモデル・推論設定・速度設定・クライアント・代表タスクで旧版と比較します。進捗のないモデル再呼び出し、親子合計の使用量、入力キャッシュ利用、検証品質、通知後の応答を分けて記録してください。Reddit投稿の削減率を合格基準にはしません。

問題があれば今回の変更箇所だけを戻し、既存の社内ルールや待機設定は残してください。
