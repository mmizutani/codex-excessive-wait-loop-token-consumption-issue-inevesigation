*Codexの使用量増加への対策：待ち時間の無駄な確認を減らします*

社内でAstra導入後にCodexの使用量が増えています。公開報告には、CIや子エージェントの完了待ちで、*同じ確認を繰り返し、作業が進まないままトークンを消費する*ケースがあります。社内の増加分のうち、これが占める割合はまだ特定できていません。

```
無駄な確認：AI -> 確認 ->「実行中」-> AI -> 確認 -> ...
目指す動作：AI -> [待機] -> 新しい結果 -> 作業再開
```
一部改善済みですが、待機機能を使える設定にするだけでなく、待ち方の指示も必要です。*Astra・Sol共通*で、次の対応をお願いします。

1. *添付のAGENTS.md追記とSkillを導入・更新してください。* 子エージェント待ちは「1回あたり最大5分、結果の通知が届けば先に再開」を基本にし、短い間隔の再確認を減らします。毎回5分待たせるものではありません。既存のルールは残し、待機の多い依頼では `$token-efficient-polling` を指定してください。
2. *長いCI待ち・人のレビュー待ちでは `/goal` を一時停止してください。* `/goal pause` -> `/goal` で `paused` を確認 -> 進められる状態になったら `/goal resume`。「待ちます」という返答だけでは停止しません。実行中の子タスクやコマンドは別途確認してください。
3. *同じ確認が続く場合は共有してください。* 使用モデル・アプリと、機密情報を除いた画面やログをこのスレッドへお願いします。

*テスト・レビュー・セキュリティ確認は省略しません。* クライアントも更新してください。削減効果はまだ未測定のため、まずは数件で、確認の繰り返しと不要な待ち時間が減るかを確認します。

導入手順はスレッド、背景と出典は添付の `EXPLANATION.ja.md` に記載しています。
