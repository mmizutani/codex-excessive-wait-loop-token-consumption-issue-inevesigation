# Codexの待ち時間の無駄を減らすための対策

Astra・Sol共通です。案内済みの待機設定は適用済みの前提です。

## 何が起きているのか

社内ではAstra導入後にCodexの使用量が増えています。公開報告には、テストや子エージェントの完了待ちで、同じ状態確認を何度も繰り返すケースがあります。ただし、社内の増加分のうち、この問題が占める割合はまだ特定できていません。[1]

```text
無駄な確認：AI -> 確認 ->「実行中」-> AI -> 確認 -> ...
目指す動作：AI -> [待機] -> 新しい結果 -> 作業再開
```

待機中ずっと文章を生成することではなく、**新しい情報がないのにAIを何度も呼び、そのたびに判断や入力処理が発生すること**が問題です。キャッシュ利用分もあるため、トークン総数・利用枠・請求額は区別して評価します。[1]

## 改善済みでも、なぜ指示の配布が必要なのか

AIを繰り返し呼ばずに待つ機能や、利用上限到達時などに自動継続を止める仕組みは、すでに提供されています。一方、待つ時間の選び方によっては、短い待機と確認を繰り返す余地が残ります。[2][3]

設定は「待機機能を使える状態にするもの」、今回のAGENTS.mdとSkillは「実際に無駄の少ない待ち方を選ぶよう指示するもの」です。設定済みでも、指示を整える意味があります。[2]

## 今回は「最大5分、通知が届けば先に再開」を基本にする

子エージェントの結果だけを待つ場面では、**1回の待機を最大5分とし、結果の通知が届けば先に再開する**方針にします。確認した待機機能は、このように通知を受けて早く戻る仕組みです。例えば2分で結果の通知が届けば、残り3分を待ち続ける必要はありません。[3]

これは「必ず5分休む」「子エージェントを5分で終了させる」という指示ではありません。何も変わっていない間だけ、短い間隔での再確認を減らすための目安です。実際の期限や利用環境の制約には従います。

5分は今回の試行用の既定値であり、効果が実測済みの最適値ではありません。必要なテスト・レビュー・セキュリティ確認は省略しません。

## `/goal` は別途一時停止する

`/goal` が有効なままだと、AIが「待ちます」と返答しても、自動継続して再び確認することがあります。今回の指示で、外部イベントを待って自動再開する機能そのものが追加されるわけではありません。[4]

```text
長い外部待ち：/goal pause -> paused を確認 -> 必要になったら再開
```

長いCI待ちや人のレビュー待ちでは、`/goal pause` の後に `/goal` で `paused` を確認し、進められる状態になったら `/goal resume` を使ってください。実行中の子タスクやコマンドは別途確認してください。[4]

## 導入後に確認すること

配布物を導入・更新して新しいセッションを開始し、待機の多い作業では `$token-efficient-polling` を添えます。具体的な手順は `SLACK_THREAD_SETUP.ja.md` に記載しています。

最初は数件で、同じ確認の繰り返し、結果が届いてからの応答、検証品質を確認してください。削減率は保証できません。同じ確認が続いたり、追加の指示が処理されにくくなったりした場合は、使用モデル・アプリと、機密を除いた画面やログを共有してください。
