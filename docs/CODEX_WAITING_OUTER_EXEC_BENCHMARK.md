# 外側の functions.exec：秒数指定とツール名の明示を比較する

## TL;DR

**2026年9月15日追記：** [現在の配布版](waiting-validation/AGENTS.waiting-compatible.md)は、利用者の指摘を受け、外側の `functions.exec`、内側の `exec_command`／`write_stdin`、実行中セルを待つ `functions.wait` の関係を明記しました。また、先頭行の `@exec` という設定構文への言及を省きました。この修正文は[別の18試験で再測定](CODEX_WAITING_PRAGMA_REMOVAL_BENCHMARK.md)しました。現在の文面の6件はすべて受入条件を満たしましたが、直前の構文あり版より応答数と入力が増えています。以下の「最終版」と測定値は、修正前の凍結済み `outer-o0n0` を指します。

- **`exec_command: 30000` と、外側の `functions.exec: 45000` の固定値を配布用パッチから削除しました。** 共通の45秒上限、長く待つ条件、内側の待機と余裕を外側に収める条件は残します。
- 外側の数値指定×ツール名の明示を比較した12試験では、秒数を省いても外側の早期復帰は0回でした。数値を重ねて書く利点は反復して確認できませんでした。
- **`functions.exec` の名指し追加は見送りました。** 数値なし版の通常コマンドでは名指しなし9応答・あり10応答、追加CI比較でも9・10応答でした。名指しの利点が得られず、少ない指示の文面を選びました。ツール名が一般に悪化を招くと証明した結果ではありません。
- 最終版は、別々の段階で測ったコマンド3件・CI2件・サブエージェント2件の計7件すべてで受入条件を満たしました。**コスト削減や通知速度の改善が全対象で一様に得られたわけではありません。** キャッシュ差により、応答が少ない方のドル換算額が高い場合もあります。
- 今回の追加調査は計32試験・140応答、API単価換算額 $5.063908 です。未完了1件と回答形式の逸脱2件も記録し、成功例の節約率へ混ぜていません。サブスクリプションの請求額ではありません。

[配布用パッチ](waiting-validation/AGENTS.waiting-compatible.md)、[日本語解説](waiting-validation/AGENTS.waiting-explanation.ja.md)、[最終選定記録](waiting-benchmark/numeric-waits/final-selection.json)

## 何を追加で調べたか

以前の[数値比較18件](CODEX_WAITING_NUMERIC_OVERRIDES_BENCHMARK.md)では、`exec_command` の30秒指定、空入力の `write_stdin` の40秒指定、実行中セルを再開する `functions.wait` の45秒指定を比較しました。**外側の `functions.exec` の45秒指定は全条件で残しており、その必要性は評価していませんでした。**

今回の問いは、外側の45秒指定にも独立した利点があるか、そして設定対象を `functions.exec` と名指しすると挙動が変わるか、の2点です。次の2つは別の設定です。

| 設定 | 対象 |
| --- | --- |
| `// @exec: {"yield_time_ms": 45000}` | `functions.exec` が JavaScript の実行結果を待つ時間。内側の `exec_command` や `write_stdin` の待機もここに含まれる。 |
| `functions.wait` の `yield_time_ms` | `functions.exec` が「セルは実行中」と返した後、そのセルの続きを待つ時間。 |

比較開始時の配布用パッチは、前者の pragma に45秒を書き、後者には待機枠内で短い確認を避けるよう定性的に指示しています。後者の45秒を追加しても効果がなかったことから、前者も不要だとは判断できません。

## 比較条件

CLI 0.154.0、Astra／low、実際のサブスクリプション認証、共有・同梱スキルの指示を無効にした環境で測ります。各試験に新しい一時 `CODEX_HOME` と作業ディレクトリを使い、同じモデルカタログと75秒のコマンドを与えます。モデル応答のモックは使いません。並行実行は最大2件、反復内の順序は固定シードで無作為化し、反復をまたぐ前にその反復の全試験を完了します。

4条件とも、初回の `exec_command` は、以前に測定した「ツールの上限と報告期限に収まる長い待機」という文面へ統一します。`write_stdin` と `functions.wait` にも具体値を追加しません。

| 条件ID | 外側45秒の明記 | `functions.exec` の名指し | 通常コマンドの反復数 |
| --- | --- | --- | ---: |
| `outer-o1n0` | あり | なし | 3 |
| `outer-o1n1` | あり | あり | 3 |
| `outer-o0n0` | なし | なし | 3 |
| `outer-o0n1` | なし | あり | 3 |

秒数を省く文面にも、先頭行の `@exec`、`yield_time_ms`、内側の待機に少しの処理時間を加えて収める条件は残します。共通ルールの「60秒の報告間隔に対して待機は45秒以内」も残します。**削除するのは、ツールごとに重ねて書いた秒数指定です。既定値を使わせる指示や、報告期限をなくす変更ではありません。**

数値ありの条件は実際の JSON 形式の pragma 例を含み、数値なしの条件は pragma とキーの名前で指定します。したがって、数字だけを機械的に取り除く実験ではなく、配布できる指示文どうしの比較です。ツール名の有無は、それ以外の同じ文章に `functions.exec` を挿入する変更です。

この12試験では、セルが早く返るような強制指定をタスクに加えません。モデルが自然に選んだ引数、実行中セルの返却、`functions.wait` による再開を記録します。選んだ文面は、比較開始時の[凍結済みパッチ](waiting-benchmark/AGENTS.compact-final.md)と、コマンド・CI・サブエージェントを各2回ずつ新規実行して確認します。サブエージェントには両条件で `fork_turns: "all"` を指定します。

## 判定と集計の方法

応答IDで重複を除き、応答ごとの入力・キャッシュ読み出し・キャッシュ書き込み・出力を各セッションの累計カウンターと照合します。親と子は別々に数えてから合算します。正しい最終結果、終了コード0、コマンドの単一起動、モデル・推論設定、スキル未使用、子の数、結果通知の遅れ、親の進捗報告間隔も確認します。

キャッシュの状態だけでドル換算額は変わり得ます。判断では、応答数と入力合計に加え、実際のツール呼び出しを確認します。外側だけが先に返って生じた再開と、75秒のコマンド完了直前で内側の待機が終わったために必要になった追加待機を区別します。

秒数の明示に繰り返し確認できる利点がなければ、利用者の方針に合わせて省きます。ツール名の明示で挙動が同等なら、設定対象を明確にするために採用し、その判断をトークン削減とは区別します。少数の比較から、統計的な同等性や普遍的な最適値を主張しません。

API単価換算には、従来と同じ2026年9月14日の Astra Standard 単価を使います。100万トークン当たり、通常入力 $10、キャッシュ読み出し $1、書き込み $12.50、出力 $50 です。長文入力の倍率は応答ごとに適用条件を確認します。書き込みの記録値0は、上流の未報告を含み得ます。**サブスクリプションの実請求額や、実際のキャッシュ書き込み数を復元するものではありません。** [単価と計算方法](CODEX_WAITING_RUNTIME_PROMPT_BENCHMARK.md#token-categories-and-api-price-dollars)

### 秒数の明記を省いたとき

名指しなしの3組では、明記あり・なしとも9応答でした。名指しありの3組では、明記あり9応答・なし10応答でした。6組中5組の応答回数は同じで、残り1組だけ数値なし版が1回多くなっています。

その1件では、初回の外側は35秒、内側は30秒で、実際には約30.2秒で JavaScript が完了しています。その後の40秒の `write_stdin` が、75秒のコマンド完了の**約0.31秒前**に戻りました。次の継続待機は即座に結果を受け取っています。外側の設定が足りずにモデルへ戻った例ではありません。

数値なしの6件は、初回の外側を31秒または35秒、継続待機の外側を45秒に設定しました。内側の待機を収めるという指示から設定できており、45秒を重ねて書く利点は反復して確認できませんでした。一方、この少数例から、数値を省けば常に同等の費用で動くとは言えません。

### ツール名を明記したとき

外側45秒ありの3組では、名指しの有無とも9応答でした。外側45秒なしの3組では、名指しなし9応答・あり10応答でした。この差は、上記の同じ1件によるものです。**名指し自体の節約効果は確認できず、観測値も完全には同じではありません。**

名指しした6試験では、継続待機に40秒を選んだものが3件ありました。名指ししない6試験はすべて44秒でした。文面によって内側の時間選択まで変わる可能性は残ります。40秒を選んでも2件は追加応答なしで完了しており、時間選択とコマンド完了のタイミングの両方が影響します。この傾向を、名指しによる確定的な効果とも、単なる偶然とも決めつけません。

4条件でキャッシュ利用率も異なっています。応答数が同じ条件間にもドル換算額の差があり、金額だけで文面の優劣を決めません。[対応する比較の集計](waiting-benchmark/numeric-waits/outer-results/comparison.json)、[実際の引数とセル返却数](waiting-benchmark/numeric-waits/outer-results/COMPARISON.md)

### 確認試験へ進めた候補

秒数を省き、`functions.exec` を名指しする `outer-o0n1` を確認候補に選びました。秒数を明記する利点が反復して確認できなかったため、利用者の方針に合わせて固定値を省きます。名指しは、どのツールの設定かをモデルと利用者が読み取れるようにする目的です。最も安かった条件を選んだという意味ではありません。

初回の `exec_command: 30000` も、以前の6組の比較と今回の全12件で明示の必要性が確認できなかったため省きます。`functions.wait: 45000` と `write_stdin: 40000` は追加しません。共通の報告期限と待機上限は残します。

### サブエージェントの未完了例を節約として数えない

候補の2回目は、子を起動する前に、`fork_turns: "all"` とモデル・推論設定の指定をどう組み合わせるか質問して終了しました。入力15,574トークン（通常3,414、キャッシュ読み出し12,160、記録上の書き込み0）、出力236トークンを消費しています。処理を完了していないため、この少ない使用量を節約効果に含めません。

試験には履歴をそろえるため `fork_turns: "all"` を追加しましたが、元のタスク文の「Astra／lowを使う」が、明示的な上書き引数を要求すると解釈されました。他の3件は、上書き引数を省略して親の Astra／low を継承できています。設定上不可能なタスクではなく、1件で不要な確認が発生した記録として残します。

また、元のパッチの1件は正しい結果に `Exit status: 0` を付け足し、結果文字列だけを返す厳密な形式チェックに違反しました。返答の追加行を消して成功扱いにする修正や、記録の除外はしていません。[確認12試験の全記録・区分別金額](waiting-benchmark/numeric-waits/outer-integration-results/COUNTS.md)、[受入確認](waiting-benchmark/numeric-waits/outer-integration-results/argument-evidence.json)

このため、サブエージェントの比較は、親の設定を継承し、上書き引数を省くことを明記した共通タスクで別途確認します。元の失敗例と消費量は残し、別条件の測定として報告します。

## 最終的に配布する文面

この測定で採用したのは、凍結済みの [`outer-o0n0`](waiting-benchmark/numeric-waits/prompts/AGENTS.outer-o0n0.md) です。以下は当時の `Terminal commands` 節です。現在の配布版には、冒頭の追記に記した文面修正があります。

```text
When only command completion remains, start `exec_command` with a long `yield_time_ms` within tool limits and the budget. Retain its session; use empty `write_stdin` waits within budget, without preliminary short polls.

In code mode, set first-line `@exec` `yield_time_ms` within budget, covering the inner wait plus a small margin. Resume running cells with `functions.wait` within budget instead of 1-second/default checks; finish the cell before polling the process again.
```
